# Decisions

One line each: what, and why. Newest at the bottom of each section.

## Tooling / project
- **Drive Unity via Unity CLI + `com.unity.pipeline`, Blender via a direct socket client to the Blender Lab add-on** — the MCP tools aren't exposed to Claude Code sessions here; these bridges offer the same capabilities (C# eval, screenshots, play mode, tests / bpy exec). See `docs/TOOLING.md`.
- **Unity 6000.6.6f1** — the only installed 6000.x editor (spec: "latest installed 6000.x").
- **Cinemachine 6.6.0** — in Unity 6.6 Cinemachine ships as a built-in package versioned with the editor (CM3 API).
- **Tests split into `Gladiator.Tests.EditMode` + `Gladiator.Tests.PlayMode`** instead of one `Gladiator.Tests` — the Test Framework decides EditMode vs PlayMode per assembly platform; one asmdef can't cleanly host both.
- **Git LFS for `.blend` and audio only; FBX/PNG stay in plain git** — procedural low-poly FBX and palette PNGs are a few KB; `.blend` files are binary and grow.
- **`Profiling/` and `Screenshots/` are git-ignored** — they're regenerable outputs; numbers that matter are copied into PROGRESS/gate reports.

## Art pipeline
- **FBX export (revised M0.4, regression-tested by `ModelPipelineTests`):** native Blender axes (`axis_forward=Y`, `axis_up=Z`), **no** `bake_space_transform`, `apply_unit_scale` + `FBX_SCALE_UNITS`, face smoothing, mesh+empty only. Unity's `ModelImporter.bakeAxisConversion = true` converts Z-up → Y-up into meshes *and* node transforms. `export_fbx` adds a temporary 180° yaw on the export root, because Unity maps Blender −Y to −Z. **Why it changed:** the CLAUDE.md §3.3 default (`-Z`/`Y` + `bake_space_transform`) passed the M0.2 box test, but the box root was a mesh. Blender's experimental bake mis-converts EMPTY nodes, and every rigid-part character root is an empty, so characters arrived lying on their backs. Four variants were compared numerically; only this one gives upright, identity-rotation parts with correct facing and handedness. Result: front +Z, left −X, 1×2×1 m exact, parts keep identity rotations, rotated joints come through as pure yaws, and the only extra transform is a 180° yaw on the FBX root node (under an identity prefab root, `preserveHierarchy`).
- **Asset front = Blender −Y** (what Blender's Front view shows) → Unity +Z.
- **Single palette source = `Assets/Art/Textures/Palette/palette.json`** → `Tools/build_palette.py` writes `PAL_Master.png` (128², 8 px swatches, 16 rows = families). Blender scripts read the same JSON for swatch UVs. Retune colours globally by editing the JSON and re-running the script.
- **Palette alpha = 1 − emission** — glowing swatches (XP, fire, VFX, affixes) come from the same texture, so no extra emissive materials are needed.
- **"One material per palette family" interpreted as: one master palette texture, shared materials split by *shader role*** (opaque lit, hit-flash, unlit VFX, transparent, crowd-instanced, blob shadow). Arena families live as palette rows. This keeps every asset on one material and gives ≤ 8 materials per scene.
- **Review renders use Workbench** (studio light for shape, then flat black at 64 px for the silhouette), composed into one contact sheet `Screenshots/blender/<name>_review.png`.

## Architecture
- **`GameLoop` = the only gameplay `Update()`**; systems implement `ITickable` and register with a `TickGroup` (Input → Player → Director → Enemies → Weapons → Projectiles → Pickups → Feedback → Camera → Late). Each tick has its own ProfilerMarker; the whole loop is wrapped in `Gladiator.Gameplay` (the "gameplay logic ≤ 4 ms" number).
- **`TimeController` owns `Time.timeScale`**: pause (level-up/menus) > hit-stop > 1. Hit-stop runs on unscaled time so it always ends.
- **Input is an `IPlayerInputSource` returning a `PlayerInputFrame` struct**; the human source builds Input System actions in code (no generated class, reproducible). PlaytestBot implements the same interface, so the bot exercises the real controller path.
- **PlaytestBot perceives the world only through `IBotSensor`** (pickups, threats, level-up, stress spawn), so gameplay systems plug in as they're built.
- **Zero-GC verification = managed-heap growth, not the "GC Allocated In Frame" counter, when running in the Editor.** In Play mode that counter includes the Editor's own allocations (~10–30 KB/frame with nothing running). `FrameStatsRecorder` also records `Profiler.GetMonoUsedSizeLong()` growth across the GameLoop window and the whole Update→LateUpdate window. It's page-granular, so any steady per-frame allocation shows up over a run; allocation-free code sums to exactly 0. Standalone dev builds use the real GC counter.
- **PlayMode tests run async** (entering play mode reloads the domain, which drops the HTTP request); `Tools/utest PlayMode` polls `test_status`.

## Look (M0.4)
- **Custom `Gladiator/PaletteLit` shader** instead of URP Lit/SimpleLit — it gives style control (wrap lighting, tinted shadows, hemisphere ambient, rim, palette-alpha emission, flash) while staying SRP-Batcher compatible and instanced. It has Forward+ (cluster loop), shadow, depth and depth-normals passes.
- **"Pixel noise" grain in the shader** (point-sampled hash on the dominant projection plane, world space for the environment, object space for characters). Megabonk's look comes largely from chunky pixel textures; this gets that retro textured feel with zero textures and the single palette material.
- **Shared materials by role:** `M_PaletteLit_Env` (grain), `M_PaletteLit_Char` (rim, light grain), `M_PaletteLit_Flash` (hit flash = swap to this shared material for a few frames; no MaterialPropertyBlock), `M_Sky`. All instanced.
- **Hemisphere ambient via `EnvironmentLighting`** (per-scene component → global shader colours + RenderSettings fog/sky). Each arena tunes its own mood.
- **URP:** SSAO renderer feature **off** (not part of the target look, needs a depth-normals prepass, costs GPU at 1080p); shadows 40 m / 2 cascades (§4 "short range"); MSAA 4×; HDR on; static batching on for Linux/Windows standalone.
- **Post (`VP_Gladiator`):** Bloom (threshold 1, intensity 0.55), Neutral tonemapping, mild contrast/saturation, vignette 0.22, slight warm white balance. The first pass was too orange (+18 saturation); pulled back.
- **Player readability mark = cyan headband + scarf tail** (player colour language). The camera sits behind the player, so the back of the character carries the cue. Enemy accent = magenta rag.

## Feel (M1.1)
- **Bake the FBX root yaw on import** (`ModelImportRules.OnPostprocessModel`: subtree conjugation p→q·p, r→q·r·q⁻¹, v→q·v). Every node arrives with identity rotation and part-local +Z = character forward, so animation and weapon code never deal with a flipped frame. Guarded by `ModelPipelineTests.AllModels_RootNodesHaveIdentityRotation`.
- **Always-run, no sprint button** (GDD Q3): run 7.5 m/s; slide and slide-jump are the speed tools (slide +4 m/s, downhill gain, slide-jump +1.5 m/s, momentum bleeds at 9 m/s² above run speed). Megabonk-like; re-check at Gate 1.
- **Slide = press to start, hold to keep sliding** (`slideRequiresHold`). Landing while holding slide → slide with no extra boost (no infinite-speed bunny-sliding).
- **Air control is Quake-style**: it accelerates toward the stick up to `airMaxSpeed` but never brakes existing momentum, so slide-jumps carry.
- **Layers: `Environment` (big geometry, camera avoids) vs `Props` (crates/barrels/fences: solid for the player, ignored by the camera)** — stops the camera popping every time a crate crosses the view.
- **Camera = CM3 OrbitalFollow (world-space binding) + RotationComposer + Deoccluder (pull forward) + Decollider (push out of grazed surfaces, terrain resolution)**, driven directly from the shared input frame. Tuning that made the bot-run clip probe go 124 → 0 frames: min pitch −8°, camera radius 0.4 m, deoccluder min distance 0.05 m. With the player backed against a pillar the camera may come within ~0.45 m of the target, so `CameraProximityFade` renders the player shadows-only below 0.75 m. `PreserveCameraHeight` was tried and was worse (34 frames, hill).
- **Procedural rigid-part animation (`PartRig` + `PartAnimProfile`)** was pulled forward from M3.3 into M1.1 in minimal form (run cycle locked to distance, idle, air, slide, land squash, jump stretch). Judging movement feel on a T-posing statue would be misleading, and the rig was already there.
- **Editor-hosted frame times are not perf data.** An unfocused Editor throttles itself (~18 fps with no bridge traffic, ~180 fps while bridge requests keep it awake). Allocation checks are valid in the Editor (heap growth); FPS/frame-time budgets are measured in standalone builds.

## Combat (M1.2)
- **Enemy core built "for real" in simple form now** instead of throwaway placeholders: struct-of-arrays state, pooled views per `EnemyDef`, one central tick, `SpatialHashGrid` (counting-sort rebuild every tick) for separation + weapon queries, `HeightGrid` for terrain, `StaticObstacles` push-out. M2.1 only extends it (scale, height-grid bake into the arena asset, perf).
- **Walkable vs obstacle is explicit** (`WalkableSurface` marker): walkables feed the height grid (highest walkable hit per cell, so wall tops never become "ground"); everything else solid and taller than 0.5 m becomes an obstacle (roundish → circle, else oriented box). A step-height rule (0.35 m per tick) stops enemies scaling walls/platform edges while stairs/ramps/hills work. Platforms are refuges ground enemies can't reach except via stairs/ramps — fine for now; ranged enemies (Phase 2) counter it.
- **Hit flash = swap the renderers' sharedMaterial to the shared `M_PaletteLit_Flash`** for 0.08 s (no MaterialPropertyBlock, SRP-batcher friendly). Compare materials by reference, never `Object.name` (allocates).
- **Slash VFX uses a MaterialPropertyBlock** for progress/arc — allowed: ≤ 6 instances, not a hot mesh.
- **Death pops = one world-space ParticleSystem with manual Emit** (one draw call for every pop). **Blob shadows = one `Graphics.RenderMeshInstanced`** for all enemies; enemy renderers don't cast real shadows (§4). The blob/gem quads are engine plumbing built in code; art meshes stay in Blender.
- **Auto-aim acquire range ≈ reach** (gladius: acquire 3.2 m, reach 2.6 m): a larger acquire range made it swing at air (6/14 swings landed → 11/5 after).
- **Hit-stop only on crits (0.035 s)**, player hits (0.05 s); screen shake is trauma² roll + tiny orbit jitter (never a position offset, so it can't push the camera into walls), scaled by `ScreenShake.UserScale` (options slider later).
- **Damage numbers: one overlay canvas, 96 pooled TMP labels kept active** (toggling UI GameObjects re-registers them with the canvas and allocates), pre-sized with the longest string so TMP never grows buffers mid-run; numeric `SetText`. Player-damage numbers are orange-red (hurts you), crits gold, normal white.
- **Stable content ids**: `EnemyDef.RuntimeId` / `WeaponDef.RuntimeId` = FNV-1a of the string id (`GetInstanceID` is obsolete in 6.6 and not stable across sessions anyway).
- **Camera: final collision guard** after CinemachineBrain (`CameraCollisionGuard`, ComputePenetration with a 0.16 m sphere) + camera radius 0.25 m (< player capsule 0.32 m, so the target is always a legal fallback). Cinemachine still does the smooth work; the guard removes the rare squeeze that the bot found with enemies around.
- **Perf numbers come from a standalone development build** (`BuildScripts`, Linux, IL2CPP default, windowed, runInBackground) run with `-bot/-stress -profile`.

## Run loop (M1.3)
- **Pickups are data + instanced draws** (`PickupSystem`: one `RenderMeshInstanced` per kind — small/medium/large XP gem, gold coin), never GameObjects. At capacity (700) new value merges into the nearest pickup of the same family, so nothing is lost and nothing allocates.
- **Base magnet radius 2.2 m < gladius reach 2.6 m.** At 3.5 m every melee kill's gems were vacuumed instantly, which makes "collecting" and pickup-range upgrades pointless. Tune at Gate 1.
- **XP curve** `xpToNext(L) = 5 + 4·(L−1)^1.35` (5, 9, 14, 19, 25, … 83 at L10) in `ProgressionConfig`; convicts give 1 XP. Placeholder until the Director (M2.3) sets real kill rates.
- **Level-up is a stub on purpose**: 7 placeholder boons that are plain stat multipliers (damage, attack speed, move speed, max HP, pickup range, reach, crit). This violates the long-term "no flat-stat grinding" rule only *within a run*, and the whole thing is replaced by data-driven cards with tags/rarity/reroll/banish in M2.4. Flow: XP threshold → 0.35 s burst beat → pause (timeScale 0, input off, cursor free) → pick (mouse / 1-4 / gamepad) → resume; queued level-ups open back-to-back.
- **Particles use scaled time**, so the level-up pause freeze-frames the burst (looks intentional; keep).
- **HUD built in code** (`Hud`, `LevelUpPanel`, `UiFactory`, procedural `PixelIcons`): XP bar top, countdown to the boss top-centre (8:00 = `runDuration`), `LV n` top-right, HP/gold/kills top-left, F3 debug line. Text changes only when values change; the timer writes a char buffer (`SetCharArray`) so the HUD is allocation-free.
- **Movement feel tests run without enemies** (a kill → XP → level-up pause would freeze their scaled-time loops); the camera test runs with enemies because fleeing produced the squeeze cases.
- **Every gem pops before the magnet can take it** (`ProgressionConfig.magnetDelay`, 0.25 s). Gems used to spawn with a random age (meant only to stagger bob/spin), which skipped the pop: melee-range gems were vacuumed — or collected — on the frame they dropped, so the drop was invisible. Age now starts at 0 and a separate random phase staggers the bob/spin. Guarded by `RunLoopTests.Kill_DropsGem_MagnetCollects_AddsXp` (the gem must be seen before it's collected).

## Test tools + run end (M1.4, producer request at Gate 1)
- **Admin menu (F1) pulled in before the playtest** so the producer can feel the effect of upgrades without grinding levels. Editor + development builds only (`Debug.isDebugBuild`); opening it pauses the game. Logic in `AdminController` (Gameplay, test-callable), drawing in `AdminPanel` (UI).
- **Admin buffs are a separate layer (`DevSettings`)** multiplied on top of the run's own bonuses (level-up cards), so "Reset buffs" never undoes a real pick. Becomes a "Dev" layer of the stat pipeline in M2.4.
- **`EnemyCatalog` asset kept current by an AssetPostprocessor**: every EnemyDef is listed the moment it exists, so new mobs/bosses appear in the spawn menu with no code change; the Director (M2.3) will read it too.
- **Death and timer end now finish the run** (a minimal early version of M3.5): death → 1.6 s real-time beat (slow motion 0.3 + collapse pose + red burst) → paused end screen with stats, Retry / Quit. Timer 0:00 → every enemy pops → "SURVIVED!" screen; once Gorm exists the timer summons him and this screen moves to after the fight. Retry reloads the scene and keeps the admin switches.
- **God mode floors HP at 1** instead of ignoring damage, so hit numbers, shake and hit-stop still read while testing.
- **The PlaytestBot runs immortal and timeless by default** (`-mortal`, `-timed` to opt out): perf and smoke runs must not end early.
- **Gameplay input blocking is a counter** (`Player.BlockInput/UnblockInput`): level-up, admin menu and end screen can overlap without one re-enabling input under another. Esc only toggles pause when no screen is blocking input.
- **Fence perimeter is the real boundary.** The fences were rotated 90° (pointing at the centre like spokes, with gaps) and purely visual, with an invisible wall 0.5 m behind them. Now each 3 m piece follows the ring so posts meet, with a 4 m solid wall collider exactly on the fence line (Environment layer: the player can't jump out, the camera stays inside). Enemies are clamped by the arena radius + obstacle bake; pickups are clamped to the arena radius.
- **Anything that pushes the static pause releases it in OnDisable** (`RunEndController`, `Player`, `LevelUpController`, `AdminController`): the full PlayMode suite froze because a test ended on the end screen and the next scene inherited the pause.

## Phase 2 (started 2026-10-18)
- **Gate 1 passed by the producer without feel changes** ("you can proceed"): all M1 config values kept; Q3 always-run (no sprint button) kept.

### M2.1 — enemy scale-up
- **Arena nav data is baked in the Editor** (`ArenaNavData` asset per arena, written by `ArenaNavBaker` when the arena is rebuilt; `EnemyManager` falls back to a runtime bake, logged, if it's missing or stale). It only saves ~14 ms on the test arena, but a 140 m Colosseum would need ~300k raycasts at load. Guarded by `ArenaNavTests` (asset == fresh bake).
- **The ~290 ms first-gameplay-frame hitch is mostly first-use rendering** (~205 ms of shader/pipeline-state creation in URP's first camera render), then Input System start-up (~18 ms), first UI layout (~17 ms) and the nav bake (~14 ms, now gone). Fix belongs to M3.5: render the arena behind a loading / "FIGHT!" beat (and try a GraphicsStateCollection / shader-variant warm-up then).
- **Perf runs use `gamescope --backend headless`** (`Tools/perfrun`): real GPU (RX 6600, radeonsi GL 4.6), 1920×1080, no window, works with the desktop locked. Numbers match windowed runs within noise (bot 979 vs 871 fps).
- **Player capture tooling:** `-rawProfile <s> -rawFrames <n>` writes a Unity Profiler capture from a dev build; `Tools/rawreport` turns it into slow-frame + GC-caller reports in the Editor. `-fps N` caps the player (smaller captures).
- **No `OnControllerColliderHit` on the player**: Unity allocates a hit object per callback (40 B per wall-contact frame). Walls are now detected from the blocked part of the move + one short capsule cast for the real normal (normal.y > 0.3 = ledge/slope, ignored).
- **Jump integration is a trapezoid step** (average of start/end vertical velocity): jump height is now exactly `jumpHeight` at any frame rate. Plain semi-implicit Euler lost ~8 cm (5 %) at 60 fps vs ~3 cm at 180 fps, so 60 Hz players jumped lower.
- **Coyote feel test now uses the platform's west edge** (a real 1.2 m drop); it used to run onto the ramp and only passed because the old wall code tripped the player on the ramp lip.
- **Collider wrappers are created at load** (`CameraCollisionGuard.Awake` touches every collider, its Transform and GameObject): Unity allocates a 24 B C# wrapper the first time script sees a native object, so the camera's overlap queries and Cinemachine's raycasts were allocating mid-run each time they met a new fence piece. After this, steady-state gameplay allocates 0 B outside the level-up UI.

### M2.2 — enemy roster
- **Sixth enemy = Fire-Pot Thrower (area denial), not the Assassin**: its burning patches only hurt you while you're on the ground, so jumping and positioning become the counter — it makes the movement kit matter. The Assassin's dash moves to Arena 2–3.
- **Elite affixes for the slice: Armored, Fast, Explosive.** Explosive blasts also damage enemies (chain reactions). Gilded waits for M2.7 so gold has a use first.
- **All "will hurt you" ground warnings go through one instanced `TelegraphRenderer`** (one extra material, `M_FxTelegraph`), keeping the scene within ~8 shared materials. Elite rings use the same renderer in the affix colour.
- **Behaviour = one state machine in `EnemyManager` (Move → Windup → Attack → Recover)**, switched on `EnemyDef.behaviour`; numbers stay in data. No per-enemy components, so 300+ enemies keep one central tick.
- **The Pit Cur's wind-up is a pose only (crouch), no ground decal.** Curs come in packs; dozens of decals would drown out the ones that matter (Brute slam, fire-pot landing). Ranged enemies get a small pulsing ring while winding up; the Brute's slam and pot landings get the full filling circle.
- **Hits are blocked by the Shield Thug's facing, not by a collider**: a hit is blocked if it comes from within `blockArc` of where the thug faces (turn rate 200°/s, so circling works). Blocked hits deal 15 %, knock back 40 %, show a grey number and never crit.
- **Elite hit-stop is rate-limited (one per 0.35 s) plus a bigger one on the elite's death.** Hit-stop on every hit would stutter constantly with a fast weapon.
- **Burning ground ("Status" damage) ignores and doesn't grant the 0.4 s invulnerability, and has no hit-stop.** Otherwise a fire patch would protect you from the crowd, and 0.5 s burn ticks would stutter the game.
- **Brute slam: jumping avoids it; a grounded hit knocks you up and away** (`PlayerMotor.AddImpulse`). Explosions don't care about jumping (they reach 1.6 m up).
- **Explosive elites leave a 1 s fuse circle at their death spot**; the blast chains to enemies. `KillAll` (run end, tests) never triggers blasts.
- **Projectiles stop at walls through the baked obstacle list, not physics.** Same data enemies use for push-out; zero colliders on projectiles.
- **Off-screen threat arrows (concern C2)**: up to 16 chevrons at the screen edge, wind-ups first (pulsing orange-red), then elites (affix colour).
- **Per-type alive counts in `EnemyManager` (`AliveOf`)**; spawners cap kiting types. Pools are prewarmed to those caps, so a pool growing mid-run is a bug and logs a warning.
- **Behaviour tests run without player i-frames** (`invulnerableTime = 0` in `EnemyRosterTests`): a random contact hit just before an attack made the attack tests flaky. The i-frame rule itself is unchanged in the game.

### M2.3 — Director
- **"Spawn budget" = a target head-count curve over run time + a fill-rate curve**, not threat points. The §8 targets are head-counts (300 by 5:00, ~500 at peak) and tougher types are already limited by low weights and caps, so points would add a second knob with no gain.
- **Per-type caps live in the spawn table** (kiting/heavy types low), fixing CONCERNS C6 at the source. The periodic elite ignores caps (it's one special enemy).
- **Swarms come from one direction** (50° arc) on top of the target, so they read as an event you can turn and face, and are announced on the HUD.
- **The Director uses the run clock**: Timeless freezes pacing, the admin timer jumps it; events missed by a jump are rescheduled rather than all fired at once.
- **Pools fill a few views per frame at run start, and spawning waits for them** (~0.8 s): no mid-fight instantiation and a smaller load hitch than one big prewarm.
- **Pool sizes come from simulating the run's head-count** (`Director.ComputePoolTargets`), not each type's weight share: capped types top out and hand their share to the uncapped ones, so by 8:00 convicts are ~330 of 460, not 32 %. Swarm types add a full swarm (swarms ignore caps), +10 % + 8 for enemies still dying. The first 8-minute run with the share formula grew the convict pool 127 times mid-fight.
- **Spawn points are a ring near the arena edge for now**, preferring off-screen. Arena 1's real gates come from its `ArenaLayoutDef` in M3.2.


### M2.4 — stats, upgrades, level-up cards
- **One `StatBlock` per player, 20 stats, value = (base + Σflat) × (1 + Σpercent) × Πmultiply.** Multiplier stats (damage, area, move speed…) have base 1, so "+12 % damage" is a Percent mod and stacks additively with other % bonuses (no runaway compounding); Multiply is reserved for rare "×" effects. Chance-like stats (crit chance/damage, armor, luck) are flat fractions shown as %.
- **Admin buffs stay a separate `DevSettings` layer**, applied on top in `PlayerStats.Get`, so "reset buffs" never undoes a real pick.
- **Rarity scales the size of the step (Megabonk-style), not which upgrade you get:** Common ×1, Uncommon ×1.4, Rare ×1.8, Legendary ×2.5 of the per-level values; whole-number stats (air jumps, rerolls, projectile count) never scale. Base odds 62/26/10/2; Luck multiplies tier r's weight by e^(1.5·luck·r) and gives a 4th card with chance luck/0.5.
- **A Boon's level = times taken (max 5)**; each take adds its step at that card's rarity. The HUD tile shows the best rarity taken.
- **Reroll redraws every card; banish removes one upgrade for the rest of the run and replaces only that card; skip is free.** Rerolls 2 / banishes 1 per run, as base stats so gladiators and Boons can change them.
- **When nothing is eligible the cards fall back to filler consumables** (Bread and Water: heal 30 %; Coin Purse: +15 gold), so a maxed build never sees an empty level-up.
- **Max-HP raises heal by the same amount; armor is % damage reduction capped at 75 %**; regen ticks every frame.
- **XP Gain is applied where XP is awarded (gem pickup), not inside `RunState.AddXp`**, so the admin "level up" button stays exact.
- **Behaviour hooks (on-hit, on-slide…) wait for M2.6**, where the first behavioural Boons need them; M2.4's Boons are pure stat data.
- **Level-up UI avoids every known allocation source:** no `Button` (colour-tint tweens), `UiHit` pointer forwarding + own highlight, shown and hidden with a `CanvasGroup` (never `SetActive` or `Canvas.enabled`: re-enabling a canvas rebuilds its graphic registry, ~8 KB per show), text from char buffers / non-allocating `SetText`, first show done hidden at load. Skip is X on keyboard (S is movement) and Select on gamepad (East is slide).
- **`GladiatorDef` exists now with base stats only**; starting weapon, signature behaviour and unlock join in M3.5.

### M2.5 — four weapons, weapon levels
- **One timeline for every pattern** (acquire → wind-up → impact → cooldown); patterns differ only in what `Impact` does. Gladius = arc around the aim, Spear = line hit (length = range × area, width × √area), Javelins = a volley at the nearest distinct enemies (extras fan out 12°), Chakram = thrown out, decelerates to a stop at its range, flies back to the hand, hitting each enemy once per leg.
- **Amount means "more of the attack" per pattern**: extra swings/thrusts right after the first for melee, extra javelins/chakrams per throw for projectiles. Player-wide Amount and Pierce stack with the weapon's own.
- **Weapon levels 2–8 are weapon-local `StatMod`s** in a `levels[]` table on the `WeaponDef`, kept in that weapon's own `StatBlock` and multiplied with the player's stats. A weapon card's rarity scales its step like a Boon's (whole numbers never scale). So "+20 % spear damage" stays on the spear.
- **Every weapon has a card (`UP_W_*`, kind Weapon)**: the first take equips it, later takes level it. 4 weapon slots; a full set only offers levels. The starting gladius is registered as owned at run start so its card shows as a level-up, not "NEW".
- **Player projectiles hit through the enemy spatial hash, not physics**, and stop at the baked obstacle list and the height grid (javelins thrown into a mound stop there). Hit memory is 16 enemies per projectile per leg.
- **Hits happen at the mesh tip** (`bounds.max.z`, read when the mesh is registered), so a javelin visibly touches what it hits and the spear tip reaches exactly its hit length.
- **Javelins and spear thrusts get a white→cyan additive streak** (crossed ribbons, drawn instanced with the slash material and a fixed property block — no new material, scene stays at 8). A brown stick 1–2 px wide didn't read at gameplay distance. Mesh scales: spear 1.25, javelin 1.6, chakram 1.3.
- **Weapon cards weigh 8 vs Boons 10** for now (first guesses, C7).

### M2.6 — statuses and behavioural Boons
- **Statuses are data (`StatusDef`): kind, duration, stacking rule, vulnerability, slow, colour.** Refresh (Burn, Shock, Slow) keeps the stronger power and resets the timer; Stack (Bleed, max 10) adds stacks and resets the timer, all stacks fall off together. Damage over time comes from whoever applies it (dps per stack), so one Burn asset serves weak and strong sources.
- **One slot per kind per enemy, in EnemyManager's struct-of-arrays**; damage-over-time and the status puffs run on a shared 0.5 s tick per enemy (not per frame), and ticks don't flash, recoil or push — hundreds of burning enemies stay readable and cheap. Puffs are capped at 48 per frame.
- **Shock = +20 % damage taken from everything**, the generic amplifier the other statuses combine with.
- **Boon effects are a small set of coded kinds (`EffectKind`) that data combines** (status on hit / on crit, chain spark, burst on death, spark bonus, damage per stack / vs status, slide trail). New Boons from these kinds are pure data; a genuinely new behaviour adds a kind.
- **Rarity scales effects through potency = the sum of the rarity steps of every take**: each kind has one headline number (chance, damage or bonus) that scales; radii, counts and durations don't. Same rule as stat Boons, so a Rare effect card is a bigger step.
- **Effects only react to direct hits; effect damage carries `DamageFlags.Proc`** and never procs again (no infinite spark/burst loops). Death bursts are queued and resolved in the tick (12 per frame), so a chain of burning enemies spreads over frames instead of recursing.
- **Synergy Boons that do nothing alone need a source first (`requiresAny`)**: Pyre needs Kindling or Conductive Oil, Conductive Oil needs Static Charge, Open Wounds needs Serrated Edge or Blood Slide. Avoids dead picks without a hidden weighting system.
- **Status colours stay in the player palette**: Burn gold, Bleed crimson, Shock cyan. Burn is not orange-red, which is reserved for what hurts the player (§5). Blood Slide's trail is a pink-crimson ring, not a fire-coloured patch.
- **18 Boons, not ~14**: the 11 stat Boons from M2.4 stay (they're the backbone of the stat build) plus 7 behavioural ones that form three synergy webs: Fire (Kindling → Pyre), Storm (Static Charge → Conductive Oil, Shock amplifying everything), Blood (Serrated Edge / Blood Slide → Open Wounds).

### M2.7 — chests, gold, shrine
- **An Armory Chest is a pick of 3 Uncommon-or-better cards, not a random item.** It reuses the level-up flow (reroll/banish/skip included) with a rarity floor, so gold buys a better, chosen upgrade and the panel says "ARMORY CHEST". Skipping after paying is allowed (your call).
- **Chest price = 15 × 1.4^chests opened** (15, 21, 29, 41, 58…), shown floating over every chest in gold (red when you can't pay). Every chest on the map costs the same, so the choice is where, not which.
- **2 chests at the start, topped up to 3, one new chest 35 s after an opening**; spots are random clear, flat ground ≥ 9 m from the player and ≥ 7 m from each other. Arena 1's layout will provide anchor points in M3.2 instead.
- **The shrine is a Blood Altar: lose 15 % max HP for good (a ×0.85 multiplier) for a pick of 3 Rare-or-better cards, once per run.** Permanent cost makes it a real decision in an 8-minute run; HP damage instead would be free at full health. One per run in the slice.
- **Interact = E / gamepad North (Y)**; North only means "banish" while the cards are open, so there's no clash. Chests and the altar have a ring (gold / crimson) and the HUD shows "[E] Armory Chest 21 gold" when in reach.
- **Reward picks open after a 0.3 s beat** (the lid pops and the gold burst plays), then pause like a level-up; queued rewards open before queued level-ups.
- **The altar is crimson (it hurts you, by your choice); chests are gold.** Neither uses the orange-red danger colour.
- **The bot buys chests it can afford within 30 m** and logs chests opened in its end-of-run summary, so perf runs exercise the flow.

### M3.1–M3.2 — Slave Pit kit and arena
- **The Slave Pit is a pit dug into the ground**: earthen walls held by planks (2.4 m) ring a 42 m dirt floor; the locals stand on the rim and on rough stands above the wall, looking down. Playable radius 20.4 m (CONCERNS C1: the larger floor), walls at 22 m.
- **Arenas are `ArenaLayoutDef` assets built by `ArenaBuilder`** (Gladiator/Arenas/Build Slave Pit): pieces by role (walkable feeds the height grid; solid and props become baked obstacles; decor has no collider), gates, mud/fire zones, crowd zones, chest/altar anchors, player spawn, a per-arena enemy cap. `SlavePitLayout` writes the first version once; after that the asset is the designer's (a separate "Regenerate (overwrites)" item exists).
- **Two gates (north, south-west): swarms and elites enter through them**, doors swinging in, so the big moments have a direction you can see coming; the steady trickle still drops in along the wall foot (ring spawns). Doors are visual only; an invisible wall behind each gate keeps the player in.
- **Mud slows the grounded player to 62 % and enemies to 70 %; sliding keeps its momentum**, so a slide is how you cross mud (movement skill pays off). Decals sit 6 cm up so the floor's height noise never pokes through.
- **Fire pits are permanent burn zones** (10 dps, grounded only — jump over them), orange-red like every hazard.
- **Vertical variety = three 1.3 m earth terraces, each with a ramp down toward the centre**, plus mounds. The altar sits on a terrace top: the risky reward is up where the horde funnels.
- **Crowd: 40 locals, one instanced draw, a 9th material (`M_Crowd`).** Tunic colour and bob phase are hashed from each spot's position in the shader; `_CrowdExcitement` (kills, elite kills, near-death) makes them cheer. Over the "≈ 8 materials" budget by one; the alternative (palette material, no animation) loses the crowd as a feedback channel.
- **Per-arena enemy cap 300 in the Slave Pit** (DirectorConfig still ramps to 460 elsewhere). C1 suggested 200–250 for readability; the perf budget holds at 300+, so I kept the §8 target and flag it for the Gate 2 playtest.

### M3.4 — Gorm, the Pit Master
- **A boss is a `Scripted` enemy in EnemyManager plus a `BossController`.** EnemyManager keeps his HP, weapon hits, statuses, damage numbers, death pop and spatial-hash presence (so every weapon and Boon works on him for free); the controller owns movement, attacks, phases and his part animation. Bosses never use per-enemy behaviour code.
- **Spec first (`docs/BOSSES.md`), tuning in `BossDef BD_Gorm`**: every wind-up, damage, size and cadence is a field. Starting HP 9,000 (a guess until the bot fight below and the Gate 2 playtest).
- **The run timer hitting 0:00 doesn't end the run when the arena has a boss** (`RunState.holdForBoss`): the boss decides it. Victory = Gorm dies (after the hoard pick); dying to him is a loss.
- **The horde is despawned silently at the entrance** (no kill events): an XP shower opened level-up cards in the middle of the entrance beat. The player keeps control during the entrance; the camera only turns toward the gate for ~2.6 s.
- **All four attacks are telegraphed in orange-red and each has its own answer**: Flail Sweep — jump it or leave the ring; Whip Lash — step out of the dotted lane (it slows); Chain Slam — keep moving (the circle stops tracking you at 60 % of the wind-up; jumping also clears it); Charge — sidestep the lane, and he stuns himself on a wall. Lanes are rows of telegraph circles (the telegraph shader only does circles).
- **Phase 2 at 55 %: a 1.5 s invulnerable roar, then a permanent ring of fire along the wall foot** (54 burning patches at 19.3 m: "he set the fence on fire"; the pit shrinks ~1.5 m), attacks 30 % faster, slams leave fire, the charge unlocks.
- **Guards every 22 s (6–10 Shield Thugs and Convicts) through both gates**: the horde comes back as pressure, never as the main fight.
- **Defeat: slow motion 0.25 for 1.8 s, "GORM FALLS!", then a pick of 3 Rare-or-better cards ("the Pit Master's hoard") before the victory screen.** In a one-arena run the pick only shows on the summary; it's there so multi-arena runs (open question) work unchanged.
- **Permanent hazard zones are fully grown from the start**: their grow-in used the zone's age, which never advanced for a zone that never ages, so fire pits only burned at their exact centre and the fire ring was invisible (found while building the boss).

### M3.5 — run flow
- **A run is `RunDef` data (an ordered list of arenas) and a static `GameSession` carries the chosen gladiator, the run and the arena index across scene loads.** Retry reloads the same arena with the same gladiator; the end screen and the pause menu go back to the menu (a bare arena build without the menu quits instead). Whether a full run chains several arenas stays open (CLAUDE.md §4); the flow already walks the list.
- **Every arena opens with a held beat (`RunIntro`): the game is paused behind the arena's name while the Director fills its pools, then "FIGHT!".** It hides the ~0.3 s first-frame prewarm hitch (Known issues since M1.2) instead of optimising it away, and gives each arena an entrance. Minimum hold 1.2 s (real time); the Director now prewarms while paused.
- **The GameLoop hands systems dt = 0 on any frame the game is paused, not just Unity's scaled deltaTime.** A pause pushed during a scene load (RunIntro's Awake) changes `timeScale` after Unity has already scaled that frame's deltaTime, so the run clock leaked one frame (0.045 s) past the intro's pause.
- **Locked gladiators already show on the select screen as dark silhouettes with a cryptic hint** (the Murder Machine, the Pit Goblin, the Blood Knight): the roster's promise is visible from the first run, at the cost of three text strings. Their real unlock state belongs to the Codex (M3.6+).
- **The main menu is a diorama of the pit (the Nobody in front, Gorm looming behind, braziers), not a flat screen**: it reuses the arena kit, so it cost nothing new to model, and it shows the game's look before the first click. `-bot` / `-stress` skip it so perf recordings start in the arena.

### M3.6 — save, Renown, Codex, the first unlock
- **Save = `SaveData` (versioned JSON, `JsonUtility`) in persistentDataPath, written through a temp file and `File.Replace`; an unreadable file is kept as `.corrupt` and the game starts fresh** instead of refusing to boot. Bot/stress runs write `save_bot.json`, and every PlayMode test runs against a sandbox file (`SaveSandbox` SetUpFixture), so automated runs never touch the player's progress.
- **The slice's unlock is Gorm's Flail: beating Gorm adds his weapon to the level-up pool** (CLAUDE.md §6.6 suggested exactly this). It's a new pattern (Orbit: spiked balls circling the player, each enemy hit at most once per cooldown, knocked outward), not a reskin, so the reward changes how a run plays. The roster table gives "Defeat Gorm" to the Murder Machine; when that gladiator is built (Phase 5) it gets a harder condition (e.g. defeat Gorm 3 times) so the two don't collide.
- **Locked rewards stay in the catalog and are filtered per run (`BuildState.Lock` from `MetaProgress.IsLocked`)**: content is still added by dropping assets in, and an `UnlockDef` only lists what it releases. The admin panel can still grant locked upgrades (dev tool).
- **Unlock conditions are an enum + id + amount (`UnlockCondition`), all of which must hold, evaluated against lifetime records after each run.** Kinds: defeat boss, reach arena, survive seconds, win with gladiator, kills with weapon, lifetime kills / gold / Renown, secret flag. An unlock with no conditions is never earned (no accidental unlocks from empty data). Renown purchases are not in the slice (BACKLOG).
- **Renown per run = 4/min survived + 2 per 100 kills + 40 per boss + 20 for winning, × (1 + 0.5 × arena index)** (`MetaConfig`). It accumulates and shows in the menu, Codex and end screen; it's the currency that will gate arena tiers and cosmetics later (nothing to spend it on in the slice, by design: meta unlocks content, never flat stats).
- **A boss kill counts even if the player dies afterwards** (`RunState.MarkBossDefeated` at the moment he falls): you did beat him.
- **The Codex is a stub screen built from the save: records, unlocks (earned in full; locked as "???" + a cryptic hint), gladiators (locked as silhouettes + hint).** No discovery tracking or secrets yet (Phase 5).

### Phase 4 — audio, announcer, options
- **Placeholder sounds are synthesised by an Editor script (`SfxSynth`: sine/square/saw/noise with envelopes and glides, 28 one-shots + a 4 s crowd loop, 44.1 kHz mono WAV)**, regenerated by Gladiator/Setup/Audio/Generate Sounds + Bank. Like the Blender scripts they're code, so they're diffable and replaceable one by one. Real audio is a later task; I can't hear them, so their levels are a first guess (all in `SfxBank`).
- **One pooled `SfxPlayer` with 24 2D voices plays everything**: per-sound minimum interval and voice cap (300 enemies being hit must not mean 300 hit sounds), distance fade and stereo pan computed from the player/camera, priority stealing. No AudioSource per enemy, no allocation. Combat sounds come from the event bus; one-off sounds (swing, chest, boss roar, gates…) are direct `SfxPlayer.Play` calls at the moment they happen.
- **The AudioMixer (Master → SFX / Crowd / Music, volumes exposed) is created through the Editor's internal `AudioMixerController` by reflection** (`MixerSetup`): Unity has no public API to create one and CLAUDE.md §4 asks for a mixer. If a future Unity breaks it, setup logs an error and the game still plays (without per-bus volumes). Mixer volumes must be applied after Awake (a mixer ignores SetFloat until it's running).
- **The crowd is audible**: a looping murmur whose volume and pitch follow `CrowdExcitement`, and a cheer whenever excitement jumps by ≥ 0.2 (elite kills, boss beats, announcer lines, FIGHT!).
- **`CrowdAnnouncer` (data in `AnnouncerConfig`)**: kill-streak ladder over a 4 s window (40 KILLING SPREE! → 80 MASSACRE! → 140 BLOODBATH! → 220 UNSTOPPABLE!), each line only when it beats the last one (ladder resets after 20 s), 6 s minimum between lines, STILL STANDING! after climbing back from < 15 % to > 40 % HP, THE CROWD ROARS! at full excitement. Silent while a boss fights (his beats own the announcer). Thresholds are set for the slice's kill rates (~15–25 kills/s late in a run); a weaker build hears fewer lines.
- **Options live in their own `options.json`** (not the progress save, so wiping progress keeps settings): master / effects / crowd / music volume, look sensitivity (multiplies the designer's camera speeds), invert Y (flips the config's setting), FOV (the resting FOV is now the option, default 62 = the old `CameraConfig.baseFov`), screen shake (scales `ScreenShake`), render scale (URP asset; the Editor restores the asset after Play mode). The music slider is there with "(no music yet)" rather than hidden, so the settings layout won't change when music lands.
- **The options screen owns Esc for the frame it closes** (`GameOptions.PanelOwnsInput`): otherwise the Esc that closes it also unpauses the game or quits from the main menu.

### Phase 4 — juice, balance, builds
- **XP curve steepened (C8): `XpForLevel = 5 + 5·(L−1)^1.6`** (was `5 + 4·(L−1)^1.35`). Early levels stay quick (level 2 at 5 XP, level 5 at 34 cumulative); a strong 8-minute bot run now ends at level 27 instead of 38–47, so the build is nearly, not fully, complete when Gorm arrives. Gorm's 9,000 HP stays: the level-27 bot still took him to 45 % in ~40 s.

- **Gems picked up in a row climb in pitch** (+0.025 per gem, up to +0.6, resets after 0.35 s): the vacuum after a big fight sounds like a payout. Numbers on `SfxPlayer`.
- **Two Linux builds: `Builds/Linux` (release: menu + Slave Pit, no admin panel, F3 shows only fps) is what a player gets; `Builds/LinuxDev` (development: + test arena, F1 admin, fps/enemy overlay) is for testing and every perf number.**

Pre-drawing the card panel during the arena intro didn't remove it, so that code was taken out again; the source is still unattributed (BACKLOG).

### Phase 5.1 — Favor (crowd gifts, Arena Master whims)
- **Favor is a separate, slow meter; `CrowdExcitement` stays the crowd's mood.** Excitement decays in seconds and drives visuals/sound; Favor fills over a run and pays out. Merging them would make gifts depend on the last 5 seconds instead of the whole show.
- **Streak and close-call Favor come from what the announcer actually says** (`AnnounceEvent.Kind/Tier`), not from a second kill counter: the crowd rewards what the player hears it notice, and there is one source of truth for streaks.
- **Style kills (sliding or airborne) earn a little Favor, capped at 3/s** (not in CLAUDE.md §6.9; my addition): movement is a power source (§5), so the crowd should love it, and the cap stops one slide through a swarm from being a jackpot.
- **Gifts are thrown 3–6 m from the player, never at their feet,** with a gold (not orange-red) landing ring: the player has to move for them, and only threats use orange-red.
- **The weapon in the sand is a loan beside the 4 slots** (`WeaponSystem.GrantTemporary`), never in the cards or the build strip: a taste of a weapon you didn't pick, without wrecking a planned build. Only unlocked pool weapons can be lent.
- **Whims add pressure, never take power away**: a gate swarm or a champion with a bounty. "Dull" needs both few kills for the horde's size *and* nobody within 6 m for ~12 s, so kiting while your weapons kill never counts; never before 1:30, never during the boss, at most one per minute.
- **Director.Instance is set in OnEnable too** (bug found by the whim tests): after the admin toggled the Director off and on, `Director.Instance` stayed null, so "Swarm now"/"Elite now" (and whims) silently did nothing.

- **Crit and elite-hit freeze frames share one cooldown, `HitFeedbackConfig.hitStopInterval` = 0.8 s** (was: elite hits 0.35 s, crits unlimited). Found by the 10-min bot run: a crit build (Lucky Cut, Serrated Edge, Quick Hands) spent 144 s of 597 s at 0.05× speed, so the 8-minute clock reached only 7:35 and Gorm never came. Earlier runs already lost 50–69 s the same way. Player hits (gated by the 0.4 s invulnerability) and elite deaths keep their own stops. The bot log now prints `hitstops N (S s)`.

### Phase 5.2 — The Pit Goblin (second gladiator)
- **One player prefab, the gladiator swapped in at spawn** (`GladiatorLoadout`, runs before every other player component) instead of a prefab per gladiator: a new gladiator is a `GladiatorDef` asset (model, `MovementConfig`, animation, camera height, weapon, traits), and the player's systems (motor, weapons, Favor, HUD) stay in one place.
- **Signature mechanics are `GladiatorTrait` assets that install a component** (Scavenger, Trap Slide): the numbers are data the producer can tune, the behaviour is code, as CLAUDE.md §2.4 asks.
- **A locked card only blocks new picks.** The goblin starts with the Bomb Satchel, whose card is held back until the goblin is unlocked; it must still level its own weapon (and a bot run with `-gladiator` works on any save).
- **The goblin's unlock also puts the Bomb Satchel in everyone's pool** (my addition): a discovery should change the next runs for every gladiator, not only add a character.
- **The crate's flag is saved the moment it breaks**, not when the run ends: a discovery must never be lost to a death or a quit. The unlock is granted at the run's end (shown on the end screen) or, if the run was quit, by the main menu.
- **Walk into the crate or press E; weapon hits don't break it** (spec said "any hit"): weapons only target enemies, and walking into a rattling box is what a curious player does. The crate stops appearing once found.
- **Root is a fifth status slot** (speed × 0, the enemy stops dead instead of easing to a stop). Scripted enemies (bosses) ignore it but still bleed, as the spec says.
- **Bombs use player colours** (a cyan-white landing ring and fuse ring) **and never hurt the player**: they are the player's weapon, so they must not look like the orange-red threats.
- **Scavenger waits while another loan is out** (a crowd's weapon in the sand): a timer must never take away the crowd's gift.
- **`GameSession.Clear()`**: a test that starts a run as the goblin leaked the choice into the next fixture (the movement test ran as a goblin at 112 % speed).

### Phase 5.3 — The Blood Knight (third gladiator)
- **Interim unlock: beat Gorm below 30 % HP** (§6.7 says "Reach Arena 3"): with one arena the knight could never be unlocked or playtested. The new `DefeatBossBelowHp` condition fits the knight (he's strongest when nearly dead) and is data, so the asset can move to `ReachArena` once more arenas exist (BACKLOG).
- **The Rite is triggered by a slide with a full meter**, not a new button: the game has no ability key, and the goblin already proved slide-triggered abilities. It's the knight's one deliberate choice: when to pay HP.
- **The Rite's HP cost is paid, not taken as damage** (`PlayerHealth.Spend`): it never kills (floors at 1 HP), and it doesn't flash, shake, hit-stop or count as a Favor close call or more Blood.
- **His blood effects reuse the Bleed crimson-pink, never orange-red**: orange-red means "this hurts you" (§5).
- **Kill heals are capped (6 HP/s)**: with 300 enemies, uncapped heal-on-kill would make him immortal at peak. All other healing is halved so the identity is "lives on kills", not "heals from everything".
- **Weapon on-hit status is weapon data** (`WeaponDef.onHitStatus`, melee patterns only for now): the greatsword's bleed is content, and later weapons (a net that roots) reuse it.

- **Crowd chatter waits a second before replacing another announcer line** (found while staging the Rite): the HUD shows one line at a time and the last one wins, so in a fight the streak and roar lines replaced "BLOOD RITE!" within a frame. Streak, Roar and CloseCall lines now never cut another kind of line off in its first second. Boss beats, gifts and the goblin's crate lines benefit too.

### Phase 5.4 — Arena 2, the Provincial Pit
- **Unlocked by beating Gorm once**, not by Renown: the climb reads as "the provinces heard about you". Renown already scales with the arena's tier (×1.5 here), so it still rewards going deeper.
- **Arena tier, not the arena's index in its run**, drives Renown, `deepestArena` and `ReachArena`: with one arena per run, every run's first (only) arena is index 0, so the index can't tell the Slave Pit from the Provincial Pit. `RunDef.Arena.tier` does.
- **The menu asks for the arena after the gladiator**, and only when more than one exists, so a new player's first run is still one click.
- **Spike traps hurt everyone** (enemies more than the player): an arena rule the player can exploit (lure the horde over a grate), not just another thing to avoid. Jumping clears them, like Gorm's sweep.
- **Barricades break only to the Champion's charge**, not to weapons: they shape the horde's paths for the whole run, and the boss fight visibly opens the arena up.
- **Arena difficulty is two multipliers on the layout** (`enemyHpMul` 1.25, `playerDamageTakenMul` 1.15) plus a tougher spawn table, not new enemy assets per arena. The damage multiplier lives on the scene's `RunState` (read by `PlayerHealth.TakeDamage`), not on the player: the player is a prefab instance, and a field the builder sets on it is not saved without a recorded override.
- **The pit's columns are its own (`SM_ProvPillar`)**: grey plinth and capital, three sandstone drums. The test-arena pillar read as a wooden post next to the stone wall. The dais seal is ochre, not red: red means "this hurts you".
- **Shield Archer** (`ShieldedRanged`): the Slinger's keep-distance loop behind the Shield Thug's frontal block (110°, 85 %), slow turn (160°/s) so flanking works. Its aim line tracks the player until 0.3 s before release, then freezes: a late sidestep dodges, a still player is hit (12 dmg, 24 m/s arrow). **The pavise dips while it recovers from a shot (0.7 s)**: the counter is "punish after it shoots" as well as "flank it".
- **Assassin** (`Dasher`): flanks to a spot beside the player (left or right of the camera's view, a little behind), not behind: an attacker fully behind a third-person camera would be unreadable. 0.6 s wind-up with the lane fixed at its start, a 7 m dash at 18 m/s (14 dmg), then 1.2 s winded and still: the window to kill it. It gives up flanking after 4 s and dashes from wherever it is.
- **A straight-lane telegraph style** (`TelegraphRenderer.Lane`, shader style 3): one stretched quad per lane instead of a row of circles. The archer's aim line, the assassin's dash, both bosses' charges and Gorm's whip use it. A cone style (`Sector`, style 4) serves the Champion's Shield Bash.
- **One boss controller, driven by data** rather than a controller per boss: `BossDef` lists the attacks each phase picks from (`phase1Attacks` / `phase2Attacks`), the words (enter / fall / guards / phase 2), and what phase 2 does to the arena (`phase2FireRing` for Gorm, `phase2SpikeVolley` for the Champion). Defaults are Gorm's, so his asset didn't change. New attacks are code (`BossAttack` gains Bash and Flurry, appended); a new boss built from existing attacks is data.
- **The Champion's shield is his body's block arc** (`EN_Champion.blockArc` 140°, 90 %), raised by the controller except while stunned, so every weapon, number and "blocked" grey hit already treats it like a Shield Thug's.
- **Only stone stops his charge**: barricades and braziers in the lane are smashed first (gone for the run), then a pillar or the wall stuns him 2 s with his guard down (+50 % damage taken). Phase 2's double charge is lost if the first one hits stone, so luring him into a pillar is the safe answer.
- **A boss's guard clock runs through the whole fight**, not only while he chases or recovers: the first 10-minute bot run with the Champion saw 0 guard waves in a minute of fight, because he attacks back to back. Paused during his entrance and phase-2 roar. Gorm now also calls his guards on time.
- **The Champion's starting HP is 13,000** (Gorm 9,000): his shield turns most frontal damage away, and the arena-tier HP bonus doesn't apply to bosses. A first guess for the playtest (C13).

## Playtest fixes (after v0.5.0, branch `phase5-playtest-fixes`)
- **The Slave Pit is twice as wide** (84 × 70 m oval, was a 42 m circle), on the producer's call after playing it. This overrides CLAUDE.md §6.2's "~35 m, claustrophobic": the claustrophobia now comes from the horde, not the walls. The run's spawn numbers are unchanged; watch the pacing (C15).
- **An enclosure, not a bowl:** the yard is at ground level and the boundary rises from it (palisade, patched fence, embankment, platforms), so the world outside is at the same level and visible over the low pieces. The old pit was dug 2.4 m down with a rim that ended in the void.
- **Invisible walls only the player hits** (Props layer) behind every boundary section, 27 m tall: low fences can stay low (you see out) without air-jump upgrades letting you climb out. Enemies are kept in by the arena's ellipse, as before.
- **Arena shape = ellipse** (`ArenaLayoutDef.aspect`, `EnemyManager.arenaAspect`): one `EdgeDistance01` / `ClampInside` / `EdgePoint` used by every system that used a radius (enemies, Director ring, pickups, chests, Favor gifts and whims, the boss, the admin spawner). Round arenas are aspect 1, unchanged.
- **Outside scenery is decor with no colliders**, placed by the layout on the surrounds' heights (a temporary mesh-collider probe at layout time). ~38k static tris for the whole arena, inside the 100k budget.
- **Crowd sound made of voices:** the old loop was low-passed noise pulsed by two fixed sine rhythms in a 4 s loop, which read as a steam train. `CrowdSynth` sums dozens of formant-filtered voices talking in phrases (no shared rhythm), with claps, whistles and a small reverb, in stereo. Two loops (murmur, roar) are crossfaded by `CrowdExcitement`.
- **The crowd reacts to bursts, and calms down:** a multi-kill (6 / 14 / 28 kills inside ~0.8 s) swells excitement with a cheer; with no kill or hit for 3.5 s, `CrowdExcitement.Activity` falls and the crowd cools to below its fighting idle, quieter and played slower (pitch 0.88: "it slows down when you're not fighting").

## Arena ladder: size and shape (producer, 2026-10-20)
- **Every arena is bigger than the previous one, compared by playable floor area.** The producer saw from screenshots that the Provincial Pit (~49 m circle, ≈ 1,900 m²) is smaller than the Slave Pit (84 × 70 m oval, ≈ 4,400 m²). The Slave Pit was doubled at the Gate 2 playtest and Arena 2 was built to CLAUDE.md's original ~50 m, so the ladder broke. Targets (about ×1.35 per step) are in `docs/GDD.md`.
- **Arenas are not limited to circles and ovals.** Each picks the outline that fits its identity (rectangle, D-shape, octagon, hippodrome...). The runtime play area must support any outline: as of v0.7.0 `EnemyManager` contains enemies in an ellipse (`arenaRadius`/`arenaAspect`), Gorm's fire ring and the bot assume it too.
- **The Provincial Pit becomes an elongated octagon: 100 × 70 m wall face with 14 m cut corners (play area 6,274 m², 1.43× the Slave Pit).** A provincial town's walled square: straight stone runs read as "built", not dug, and differ at a glance from the Slave Pit's oval stockade. Cut corners keep the horde from pinning the player in a 90° corner.
- **Any outline goes through one radial table in `EnemyManager`** (720 bins of centre → edge distance, built once from `ArenaLayoutDef.outline`). Every system already asked `EdgeDistance01` / `ClampInside` / `EdgePoint`, so the octagon needed no changes outside `EnemyManager` (plus Gorm's fire ring, now sized by `EdgePerimeter`). Per-enemy containment only does the lookup outside the inscribed circle. Limit: the outline must be visible in full from the centre (true for the rectangle, D-shape, octagon and hippodrome in the GDD). The Slave Pit keeps its exact ellipse path.
- **Four gates, one mid-side, instead of three.** A floor three times bigger needs entrances on every side, or swarms take too long to arrive from the far end. The north gate stays the boss's.
- **Wall sections are scaled to fit each straight edge exactly.** Overlapping coplanar pieces would z-fight on a straight run (the old ring got away with it at an angle). Stone piers cover the eight corner joints, and a narrow stand fills the gap each bend leaves behind it.
